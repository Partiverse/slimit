# 设置功能设计评估（2026-10-02）

> 问题：是否适时增加「设置」功能，让软件核心功能更聚焦？
> 结论先行：**是，但只做一件事——把「非清理主线」的配置从界面各处收拢到一个「设置」页**，清理页只留与当前任务直接相关的控件。新增页面数不增加（并入现有「高级」页改造为「设置」）。

## 1. 现状盘点（哪些配置散落在哪里）

| 配置项 | 现位置 | 问题 |
|---|---|---|
| 新手档开关 | 清理页顶栏 | 与筛选器（只看 ≥ / 闲置 ≥）挤在一行，语义混杂：新手档是「偏好」，筛选是「本次任务」 |
| 大小/闲置筛选 | 清理页顶栏 | 属于当前任务视图，**应留在清理页** |
| FDA 权限引导卡 | 高级页顶部 | 一次性引导，长期占据版面；应改为「未授权时出现、授权后消失」的按需提示 |
| AI 设置（端点/Key/模型/测试） | 高级页内嵌 | 典型设置项，位置合理 |
| 卷宗/APFS 快照 | 高级页 | 高级诊断功能，位置合理 |

## 2. 设计方案（shadcn 语义：Settings = 分区表单）

- 「高级」页改造为「**设置**」页，分三区：**权限**（FDA 状态+引导，未授权时强化显示）/ **AI 解释**（现状保留）/ **高级诊断**（卷宗、快照）。
- **新手档迁入设置页**（偏好），清理页顶栏只留两个筛选下拉；设置页开关即时生效（状态已在 App 层，提升为共享状态即可）。
- 首次运行体验：FDA 未授权时，清理页顶部横幅（现有）+ 设置页强化卡片（现有），双入口但都不阻塞。
- 明确**不做**：主题切换（跟随系统）、语言切换（只有中文）、开机自启（v0.1 不承诺）、过滤规则自定义（规则库走 issue 流程，见 rules/README）。

## 3. 评估理由

- 收益：清理页顶栏从 5 个控件减到 3 个（输入框/扫描/两个筛选），主任务视觉焦点集中；「偏好」与「任务」语义分离，符合新手心智。
- 成本：低——全部是已有控件的重新归位，无新后端（noviceMode 状态提升）。
- 时机：**现在做正合适**（rc10 前的界面定稿窗口），晚于 rc10 会让种子用户在旧布局上形成习惯再改。

## 4. 验收清单（实现时逐项真机验证）

- [ ] 设置页三区齐备，新手档开关在设置页且即时影响清理页
- [ ] 清理页顶栏只剩：路径输入、开始扫描、两个筛选
- [ ] FDA 未授权时清理页横幅与设置页卡片双入口；授权后横幅消失
- [ ] AI 测试连接在设置页可用
- [ ] 全部功能穷举真机验证（见 AGENTS.md 规矩）
